## 1. 문제 정의

교육 현장의 강의 품질 평가는 수강생 만족도 조사나 관리자의 주관적 관찰에 의존합니다. 기준이 일관되지 않고 강사가 구체적인 개선 방향을 얻기 어렵습니다. STT로 전사된 강의 스크립트 15일치를 **5개 카테고리 · 18개 항목 체크리스트**로 자동 평가하고, 근거 발화와 함께 강사용 개선 리포트를 생성하는 시스템을 만들었습니다.

## 2. 내가 한 일

### 화자 EDA와 1차 전처리

원문은 `<09:11:17> b54f46b0: 발화` 형식의 STT 로그였습니다. 화자별 발화 수를 뽑아 보니 파일마다 화자가 1~3명으로 달랐고, 발화 4건짜리 잡음 화자도 있었습니다. 처리 선택지(삭제 / 메인 화자 병합 / 별도 보존)를 문서로 정리한 뒤, **전체 발화량 5% 이상인 화자만 메인 화자로 남기고** 타임스탬프와 화자 ID를 제거하는 스크립트를 작성했습니다.

### IT 전문용어 교정

STT가 기술 용어를 발음대로 적어 놓았습니다. `마이에스q엘`, `마S큐L` → `MySQL`, `잡아이오` → `Java IO`처럼 **표준 용어 하나에 여러 오인식 변형을 매핑하는 치환 사전**을 만들어 15개 파일에서 388건 이상을 일괄 교정했습니다. 파일별 교정 건수를 터미널에 리포트해 교정 품질을 추적할 수 있게 했습니다.

### 평가 프롬프트 설계

18개 항목마다 세부 기준, 분석 방법, 고득점·저득점 조건을 명시하고, 5점 척도와 항목별 가중치(높음 ×3, 중간 ×2, 낮음 ×1)를 반영한 프롬프트를 작성했습니다. 실행기는 환경변수 하나로 Gemini와 GPT-4o를 바꿔 호출할 수 있게 해 모델 비교가 가능한 구조로 두었습니다.

### 리포트 생성기 리팩토링 — 핵심

기존 구조는 원문 스크립트를 LLM에 통째로 넘겨 **"처음부터 다시 분석하고 리포트를 써라"**는 원샷 방식이었습니다. 문제는 팀원의 분석 엔진이 계산한 점수와 LLM이 다시 낸 점수가 **엇갈린다**는 것이었습니다. 같은 강의에 두 개의 진실이 생겼습니다.

해결은 **역할 분리**였습니다. LLM의 역할을 "분석"에서 "리포트 합성"으로 바꿨습니다.

```
분석 엔진(Python)          →  점수 · 라벨 · 근거 문장 · 커리큘럼 일치도   (단일 진실)
전처리 계층(Python)        →  가중 평균 → A+~F 등급, 인과 문장, 4단계 라벨,
                             하위 3개 항목 "최우선 개선" 태깅, 근거 100자 트리밍
생성 LLM(Gemini)           →  주어진 수치를 절대 바꾸지 않고 서술과 포매팅만 담당
```

- 등급, 라벨, 우선순위처럼 **코드로 결정할 수 있는 것은 전부 코드에서** 결정해 JSON에 넣어 주었습니다. LLM이 점수를 지어낼 여지를 없앴습니다.
- 출력에 타밀어 등 외국어 문자가 섞이는 환각이 있어 한국어 강제와 고정 문구 규칙을 프롬프트에 넣었습니다.
- SDK 대신 REST를 직접 호출하고 모델명과 키를 환경변수로 분리했습니다. 응답을 감싸는 마크다운 코드블록은 후처리로 제거합니다.

### 일간 결과 × 장기 추세 통합

리포트 페이로드를 `daily_result`(오늘)와 `historical_trajectory`(15회차 누적) 두 축으로 구성했습니다. 오늘 감점된 항목이 누적 약점 패턴과 겹치면 **"누적 분석 Alert"**를 붙여, 일시적 실수인지 구조적 약점인지 구분해 서술하도록 했습니다.

## 3. 결과

- 5개 카테고리 · 18개 항목 진단, 7개 섹션(종합 등급 · 역량 프로필 · 항목별 근거 발화 · 강점 · 개선점 · Action Plan) 리포트 자동 생성
- 15회차 궤적 기준 누적 약점 상위: 불필요한 반복 표현 15/15, 언어 일관성 13/15, 실습 연계 12/15
- 최종 리포트 5건 제출, 2주차 중간발표와 최종발표 담당

팀 전체로는 E5 임베딩 기반 근거 문장 추출(BGE-M3와 비교해 과분할이 적은 e5 채택), Gemini 2.0 Flash 항목 진단, 휴리스틱 점수와 LLM 점수를 가중 합산하는 하이브리드 스코어링을 함께 구성했습니다.

## 4. 회고

1. **LLM에 두 가지 역할을 동시에 맡기지 않는다.** 분석과 서술을 분리하자 점수 불일치와 환각이 함께 줄었습니다.
2. **코드로 결정할 수 있는 것은 코드로 결정한다.** 등급과 우선순위를 미리 계산해 넘기면 LLM은 틀릴 곳이 없습니다.
3. **STT 전처리는 점수보다 해석 품질을 올린다.** 용어 교정은 정량 점수를 바꾸지 않았지만 근거 문장과 LLM 입력의 가독성을 크게 높였습니다.
